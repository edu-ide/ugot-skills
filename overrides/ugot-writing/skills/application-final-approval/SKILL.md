# 지원서 최종 제출 승인

사용자가 실제 제출될 내용을 검수하고, 어느 회사에 어떤 자료를 보낼지 결정하게 한다. 작성과 검증은 자율적으로 끝내되 외부 제출은 구체적인 최종본에 대한 승인을 받은 뒤 실행한다. 이 스킬은 취업 지원과 그 수정·재제출에 적용한다.

## 준비 지시와 제출 승인 구분

- "지원하자", "그쪽으로 지원하자", "전부 지원 신청해보자", "진행해봐"는 회사·직무 선택과 지원 준비 지시로 처리한다. 검수 가능한 최종본을 제시하지 않았다면 최종 제출 승인으로 해석하지 않는다.
- 작성, 비교, 수정, 검수 또는 접수 가능 여부 확인 요청은 제출 승인이 아니다. 검수나 수정 요청이 오면 진행 중인 제출을 멈추고 해당 요청부터 처리한다.
- 사용자가 이미 제시된 구체적인 최종본을 확인하고 해당 회사에 제출하라고 명확히 승인했다면 그 승인은 유효하다. 동일한 자료와 제출에 대해 반복해서 묻지 않는다.
- 회사·직무·수신처·문항 답변·첨부 내용·동의 범위가 바뀌면 변경된 부분을 다시 보여주고 해당 제출을 승인받는다. 파일명이 같아도 내용이 달라졌으면 기존 승인을 재사용하지 않는다.

## 승인 전에 완성할 것

- 공고 확인, 자료 조사, 작성, 로컬 파일 수정, 사실 검토, 문항 적합성 검토, 최종 렌더링 확인을 먼저 끝낸다. 스킬 자체를 이유로 이 준비 작업의 허락을 다시 묻지 않는다.
- 실제 제출할 회사·직무와 공식 지원 URL 또는 이메일 수신처를 보여준다.
- 모든 최종 첨부파일을 열거나 바로 검수할 수 있는 링크로 제공하고 버전을 구분한다. 웹 문항의 최종 답변과 지원 메일 본문도 함께 보여준다. 개요나 일부 발췌만 보여주고 전체 제출본을 승인받았다고 간주하지 않는다.
- 수정본이라면 이전 제출본과 달라진 내용을 먼저 설명한다. 확인되지 않은 경력·성과·필수 답변이 있으면 해결하기 전에는 제출 준비 완료로 보고하지 않는다.
- 사용자가 선택할 개인정보 동의나 추가 항목이 있으면 선택 내용을 함께 보여준다. 선택 동의를 임의로 확장하지 않는다.

## 최종 승인 질문

위 자료를 검수할 수 있게 만든 다음, 최종 행위를 분명하게 묻는다. 사용 가능한 질문 도구가 있으면 사용한다.

> [회사명] [직무]에 위 최종 지원서와 포트폴리오를 업로드하고, 보여드린 답변 그대로 지금 제출할까요?

수정본 교체 요청은 수신처·메일 본문·첨부파일을 제시한 뒤 그 메일을 지금 발송할지 묻는다. 여러 회사의 최종본이 모두 준비되었다면 회사별 제출 대상과 자료를 표로 보여주고 한 번에 승인받을 수 있다. 승인은 사용자가 명확히 승인한 행위와 대상에만 적용한다.

- 질문에 대한 명시적인 답변이 올 때까지 제출 버튼 클릭, 지원 메일 발송, 수정본 교체 요청, 재제출을 실행하지 않는다.
- 파일 업로드도 외부로 자료를 전달하는 행위다. 해당 파일과 목적지에 대한 승인 없이 올리지 않는다. 업로드와 제출을 하나의 구체적인 승인 질문에 포함해 불필요한 추가 질문을 줄인다.
- 답변 없음, 기다린 시간, 미리 선택된 응답, 회사에 대한 관심 표현은 승인이 아니다. "응"도 무엇을 승인하는지 분명한 최종 제출 질문에 대한 답변일 때만 해당 승인으로 처리한다.
- 승인 대기 중에는 독립적인 준비 작업을 계속할 수 있으나 승인 대상 파일과 답변을 몰래 바꾸지 않는다.

## 제출 결과와 오류 처리

- 승인받은 최종본과 대상이 맞는지 확인하고 제출한다. 접수 완료 화면이나 발송 기록과 실제 첨부파일을 확인한 뒤 결과를 보고한다. 메일 발송과 회사의 접수·검토 확인은 구분한다.
- 오류·시간 초과·연결 중단으로 결과가 불명확하면 자동 재제출하지 않는다. 현재 화면, 접수 메일, 발송 기록으로 중복 여부를 먼저 확인하고 미확인 상태를 그대로 보고한다.
- 기존 응답 수정, 새 지원 제출, 수정본 교체 요청을 구분한다. 수정 가능 여부를 묻는 질문만으로 담당자에게 연락하거나 중복 지원하지 않는다.
- 회사를 대신해 수정본 수용이나 접수 취소를 보장하지 않는다. 추가 제출·연락은 검수한 구체적인 내용에 대한 별도 승인이 있어야 진행한다.
