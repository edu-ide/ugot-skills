# AI 아키텍처 설계 협의

협의는 설계의 빠진 조건을 찾고 서로 다른 가설을 판별하는 작업이다. 합의 여부보다 근거와 실행 가능한 결정에 가치를 둔다. 적용 대상은 AI 모델의 구조·기억·학습 메커니즘 설계다.

## 실제 협의 수단을 확인한다

사용자가 특정 모델이나 상대를 지정했으면 실제 이용 가능한 수단과 세션의 기존 허가를 확인한다. 상대를 바꾸고도 지정된 모델과 논의했다고 하지 않는다. 실제로 호출하지 못했으면 그 사실을 밝히고, 가능한 독립 검토를 정확한 이름으로 표시한다. 대체 검토를 마쳐도 지정된 상대와의 협의는 미완료로 남긴다.

이미 허용된 협의에는 같은 허가를 다시 묻지 않는다. 이 스킬 자체는 새로운 상대에게 연락하거나 비공개 자료를 전송할 권한을 부여하지 않는다. 외부 협의가 불가능해도 허용된 코드 확인·문헌 연구·구현은 계속한다. 특정 CLI 경로·모델 버전·도구가 항상 존재한다고 가정하지 않는다.

## 검토에 필요한 자료를 전달한다

현재 목표, 전체 후보의 상태·갱신식·입출력, 실제 코드·결과, 비교군·자원, 핵심 미확인 조건을 간결하게 전달한다. 원문을 제공하지 않고 상대가 읽었다고 가정하지 않는다. 결과·구현과 설계 제안을 구별한다. 검토자가 접근하지 못한 자료의 한계를 남긴다.

독립 검토자에게 처음부터 원하는 결론이나 자신의 진단을 정답처럼 주지 않는다. 후보를 이해할 자료와 다음 과제를 제공한다.

- 필요한 정보를 구별할 수 없는 층, 누락된 학습 신호, 잘못된 상태·갱신 계약을 찾아 반례를 제시한다.
- Attention·MLP·Q/K/V뿐 아니라 입력·숫자 표현·커널·학습·영속화 경계까지 문제의 원인이 내려가는지 검토한다.
- 가장 치명적인 반론, 기존 방법으로 설명되는 부분, 제안하는 대안과 이를 구분할 실험을 제시한다.
- 현재 근거로 결론 낼 수 있는 범위와 검토하지 못한 범위를 구분한다.

자신도 같은 쟁점에 대한 검토를 수행한다. 필요하면 수학·구현, 선행 연구, 평가·비용을 독립적으로 분담하되 검토 결과는 하나의 전체 후보 결정으로 합친다.

## 핵심 연산 재설계를 병행한다

AI 아키텍처 개발에서는 Attention·MLP·Q/K/V 등 계산 원리의 재설계를 긴 학습이나 상위 기능 구현이 끝난 뒤로 자동 미루지 않는다. 사용자의 2026-10-08 교정에 따라, 실제 의존성이 없는 원리 설계·전체 후보 구현·CPU 검증·문헌 연구·독립 검토를 기존 실험과 병행한다. GPU 점유나 협의 응답 대기는 독립적인 구현을 멈출 이유가 아니다. 공유 자원·미확정 입력처럼 실제로 의존하는 부분은 그 이유와 진행 가능한 부분을 구분한다. 대안을 문서에만 남기거나 사용자 재질문을 착수 조건으로 삼지 않는다. 동결 실험을 보존하고, 신규성·구현·성능 판정을 분리한다.

## 답변을 검증하고 다시 묻는다

상대의 제안·인용·수학·구현 주장에 원문·코드·실행 증거를 요구하고 직접 대조한다. 실험하지 않은 조언을 실측이나 증명으로 기록하지 않는다. 새 설계를 제안받으면 그 설계가 원래 문제를 실제로 없애는지, 다른 층으로 옮기는지 다시 검토한다.

재질문에는 구체적인 반례·새 자료·남은 모순을 담는다. 같은 질문을 반복해서 동의를 얻거나 다수결로 성능을 판정하지 않는다. 서로 다른 예측을 내는 가설은 예측과 반증 조건을 고정한 실험으로 넘긴다. 새 근거 없이 주장이 반복되면 협의 회차를 끝내고 구현·검증으로 전환한다. 새 결과가 나오면 협의를 다시 연다.

[범용 자기질문](../self-questioning/SKILL.md)의 AI 아키텍처 층별 점검과 연결한다. 자기질문은 다른 분야에도 적용되지만 이 협의 스킬의 적용 범위는 AI 모델 설계로 유지한다. 이미 적용 중이면 같은 스킬을 재귀적으로 재실행하지 않고 현재 결정에 검토 결과를 반영한다. 사용자가 문제를 다시 지목할 때까지 기다리지 않는다.

## 남길 결과

기존 작업 기록에 다음을 남긴다. 대화 전문이나 상세한 내부 사고를 보고서 본문에 붙일 필요는 없다.

- 실제 검토자·모델, 호출 여부, 확인 가능한 실행·세션 식별자와 자료 범위. 도구가 주지 않은 ID나 비용은 만들지 않는다.
- 쟁점별 제안·반론, 대조한 근거, 채택·수정·보류·기각과 이유.
- 전체 후보에 반영할 변경, 사전 예측, 다음 판별 행동과 미해결 조건.
- 원출력·코드·실험 기록의 실제 경로. 민감한 자료는 허용된 위치와 범위 안에서 다룬다.

‘Fable과 합의했다’, ‘독립 에이전트가 동의했다’는 성능이나 새로움의 근거가 아니다. 설계 협의 완료, 구현 완료, 구조 검증, 실제 성능 판정을 각각 보고한다.
