# 한국어 문체 교정

독자가 한 번 읽고 뜻을 이해할 수 있도록 한국어 문장을 다듬는다. 작성자가 하지 않은 생각이나 경험을 보태지 않는다. 필요한 설명과 작성자의 개성을 남긴다.

## 원문과 문체 기준

- 수정할 원문, 독자, 글의 목적, 요청된 말투·분량을 먼저 확인한다. 대화에서 이미 알 수 있는 사항은 다시 묻지 않는다.
- 사용자가 제공하거나 승인한 글을 문체 기준으로 삼는다. 설명용 예문이나 AI가 쓴 초안을 사용자의 실제 글로 간주하지 않는다. 기준 글이 없으면 원문의 존댓말, 어휘 수준, 관점과 문단 흐름을 유지한다.
- 여러 문체가 섞인 자료에서는 이번 독자와 용도에 맞는 예시를 고른다. 채팅 말투를 사업계획서에 옮기거나 보고서 말투를 개인 글에 강요하지 않는다.
- 긴 문서의 목차·주장·사업 전략까지 다시 설계하지 않는다. 구성 변경을 요청받았을 때만 그 범위를 넓힌다.

## 문장을 고치는 기준

문제 표현이 문장에서 무슨 일을 하는지 판단하고 고친다. 단어를 금지 목록으로 처리하거나 같은 뜻의 상투어로 교체하지 않는다. 구체적인 예외와 사례가 필요할 때 [교정 사례](references/editing-examples.md)를 읽는다.

- **번역투:** 불필요한 명사화, 피동, 긴 관형절을 실제 주체와 동작으로 풀어 쓴다. 주체를 원문에서 알 수 없으면 지어내지 않는다.
- **기계적인 대조:** “A가 아니라 B”가 주장만 강조하고 A를 부정할 근거가 없으면 B를 직접 설명한다. 잘못된 정보를 바로잡거나 실제 차이를 설명하는 대조는 유지한다.
- **빈 수사와 관용구:** “조용히”, “말 그대로”, “본질적으로”, “~를 떠받친다” 등이 구체적인 뜻을 더하는지 본다. 실제 소리·태도·구조를 나타내면 남긴다. 없던 원인이나 효과를 보태서 구체화하지 않는다.
- **문장 연결:** 대시와 접속사를 기호만 바꿔 처리하지 않는다. 앞뒤 관계가 원인, 결과, 보충, 대조 중 무엇인지 보고 문장 구조를 다듬는다. 원문에 없는 인과관계를 만들지 않는다.
- **반복과 리듬:** 비슷한 길이의 문장, 같은 첫말·끝말, 반복되는 구호를 자연스럽게 조정한다. 모든 문장을 짧게 만들거나 구어체로 바꾸지 않는다.
- **목록과 마무리:** 항목 수를 내용에 맞춘다. 필요한 절차·비교·독립 항목은 목록으로 남긴다. 마지막 문장이 앞의 말을 되풀이하기만 하면 덜고, 새로운 결론이나 다음 행동이 있으면 유지한다.

적절한 문장은 그대로 둔다. 요약·축약 요청이 없으면 필요한 사례와 조건을 지우지 않는다. 일부러 오탈자, 속어, 가짜 일화나 불규칙한 문장을 넣지 않는다.

## 내용 보존

교정 전에 다음 내용을 확인하고 교정 후 원문과 대조한다.

- 수치와 단위, 날짜, 제품명·사람명·기관명, 링크와 출처.
- 직접 인용과 코드. 사용자 요청이 없으면 인용 안의 표현도 교정하지 않는다.
- 누가 무엇을 했는지, 원인과 결과, 비교 대상, 범위와 조건.
- 부정, 가능성, 확신의 정도, 계획·진행·완료의 구분. “할 수 있다”를 “한다”로 바꾸지 않는다.

파일로 된 원문을 고칠 때는 원문을 임시 파일로 보관한 뒤 결과와 자동 검사를 실행한다. 붙여 넣은 글도 길거나 보호할 내용이 많으면 원문과 결과를 임시 파일로 저장해 검사한다. 임시 파일은 결과 확인 뒤 정리한다. 스킬 폴더에서 다음 명령을 사용한다.

```bash
python3 scripts/check_preservation.py original.txt revised.txt --protect '보존할 고유명사'
```

`--protect`는 실제 원문에 있는 이름이나 용어를 지정하고 필요하면 반복한다. 숫자·단위, URL, 인용문, 백틱 코드와 명시한 용어를 검사한다. 차이가 있으면 원문을 대조해 복원한다. 사용자가 명시한 사실 수정이나 요약 때문에 생긴 차이는 요청된 변경인지 확인하고 결과 보고에 그 범위를 밝힌다. 검사를 통과시키려고 필요한 내용을 빼거나 검사 대상에서 몰래 제외하지 않는다.

**자동 검사는 의미 보존의 증명이 아니다.** 숫자의 대상 바뀜, 부정·조건·인과관계 변경, 한글로 쓴 숫자와 지정하지 않은 고유명사는 문장 단위로 직접 확인한다. 통과 결과를 “사실 검증 완료”로 표현하지 않는다.

새 글을 쓸 때는 제공된 사실과 자료를 기준으로 초안을 작성한 뒤 같은 문체·의미 대조를 수행한다. 긴 자료를 압축한 초안에 원문의 모든 숫자와 인용 횟수를 강제로 맞추지 않는다.

## 결과와 개선

- 기본 결과는 교정한 글이다. 사용자가 설명이나 비교를 요청했을 때 변경 이유와 중요한 차이를 함께 제공한다. 보존 문제를 해결하지 못했다면 그 부분을 짧게 알린다.
- “AI 냄새 제거율”, 탐지기 점수, 단어 개수만으로 품질을 주장하지 않는다. 기계 검사와 사람이 읽고 판단한 결과를 구분한다.
- 사용자가 승인한 실제 전후 사례를 다음 작업의 문체 기준으로 활용한다. 장기 저장은 사용자가 요청한 범위에서만 하고 개인 문체 예시를 외부에 전송하거나 공개하지 않는다.

회귀 검사는 스킬 폴더에서 `python3 -m unittest discover -s scripts -p 'test_preservation.py'`로 실행한다. 이 검사는 내용 보존 검사 도구를 검증하며 글의 자연스러움까지 평가하지 않는다.
