# 스킬 사본으로 작업 진행하기

선택한 업무 스킬을 읽은 뒤 이 절차로 작업용 사본을 준비한다. 요청의 범위·대상·권한은 최신 사용자 지시를 따른다. 사본 생성은 업무 수행이나 준수 완료를 뜻하지 않는다.

## 사본 준비

1. 현재 작업과 적용할 스킬의 실제 경로를 확인한다. 이전 작업의 사본이 있으면 먼저 읽고 이어 간다. 새 작업 또는 명시적인 스킬 버전 변경 시 새 시각 폴더를 만든다. 원본과 과거 기록을 덮어쓰지 않는다.
2. 아래 도우미를 실행한다. `--skill`을 반복해 함께 적용할 스킬을 지정한다. `source/`는 보존용, `working/`은 주석을 추가할 작업용이다. 도우미는 스킬 폴더의 참조·스크립트·자산을 함께 복사하고 파일별 SHA-256을 `manifest.json`에 기록한다. `.git`과 `__pycache__`는 제외하며, 내부 심볼릭 링크는 오류로 알린다. 링크 때문에 실패하면 필요한 참조 범위를 확인해 별도 일반 파일 사본을 준비하고 그 경위를 기록한다.

```bash
python3 /absolute/skill-run/scripts/skill_run.py create \
  --skill /absolute/task-skill \
  --workdir /absolute/current-task \
  --timezone Asia/Seoul \
  --session-uri <session uri>
```

## 요구사항과 이행 표시

3. [criticmarkup](../criticmarkup/SKILL.md)을 읽고 `working/<스킬>/SKILL.md`의 해당 요구사항 바로 뒤에 실행 주석을 붙인다. 원문의 규칙·기존 주석·코드·YAML은 보존한다. 식별자는 보존본의 줄과 연결하고, 한 항목에 여러 조건이 있으면 조건별 이행을 구분한다. 현재 사용자 제약은 별도 항목으로 적고 발언을 연결한다. 참조 문서에서 실제 실행에 필요한 조건도 해당 사본에 표시한다. 자동 추출한 줄 목록을 모든 요구사항의 목록으로 간주하지 않는다.
4. 각 주석에 항목·읽음·실행·검증·근거·다음을 남긴다. 저장소 연결 문법의 기존 키를 사용해 `대상=항목 ID와 원문 위치; 확인=읽음:예/아니오; 실행=상태; 상태=검증:상태; 출처=실제 근거 링크 또는 미확인; 조치=다음:할 일`로 쓴다. 실행은 `미착수/진행/완료/위반/해당없음`, 검증은 `미확인/통과/실패/해당없음`으로 구분한다. 완료에는 실제 산출물·로그·화면과 확인 범위를 붙인다. 해당없음에는 조건과 제외 이유를 적는다. 기준이 불명확하면 충족으로 처리하지 않고 필요한 확인을 적는다.

```text
{>>실행: 대상=소재-01, source/shorts-creator/SKILL.md:L24; 확인=읽음:예; 실행=위반; 상태=검증:실패; 출처=[현재 대화][request] 조회수 비교 누락 확인 발언; 조치=다음:조회수와 적합성이 확인되는 후보를 비교한 뒤 선정<<}
```

## 작업 진행과 단계 대조

5. 다음 행동 전에 그 행동의 선행 요구사항과 최신 사용자 제약을 사본에서 대조한다. 필수 선행 조건에 위반·실패·미확인이 있으면 그 조건을 충족하거나 실제로 적용되지 않는 이유를 확인할 때까지 종속 작업을 진행하지 않는다. 독립적으로 가능한 작업은 계속한다. 이후 단계의 미착수 항목이나 조건부 항목까지 일괄 차단하지 않는다.
6. 결과를 얻을 때마다 해당 주석을 갱신한다. 실패를 수정했으면 실패 근거와 수정 후 검증을 함께 보존한다. 사용자 지시·원본 스킬이 바뀌면 변경 전 기록을 남기고 영향받는 항목을 재검토한다. 원본 스킬의 실수를 발견해도 작업 사본만으로 공통 원본까지 수정·배포했다고 보고하지 않는다.
7. 종료 전 보존본을 아래 명령으로 확인하고, 작업 사본을 직접 읽어 요청·필수 조건·실제 결과를 대조한다. 이 명령의 성공은 보존본 해시 일치만 뜻한다. 업무 성공·근거의 타당성·주석 완전성은 별도로 확인한다. 최종 답에는 작업 사본 링크, 수행·검증한 범위와 미충족 조건을 남기며 연결된 Work가 있으면 정확한 작업 ID에 결과를 기록한다.

```bash
python3 /absolute/skill-run/scripts/skill_run.py verify --run /absolute/current-task/timestamp
```

스킬 사본만으로 모든 도구 실행을 강제하거나 이 스킬 자체의 선택 누락을 막을 수는 없다. 적용 시작 지시나 사용하는 실행기의 진입점이 함께 필요하다. 이번 절차의 재발 방지 효과는 후속 작업에서 선행 조건 누락과 근거 없는 완료가 발생하는지 확인해 판단한다.
