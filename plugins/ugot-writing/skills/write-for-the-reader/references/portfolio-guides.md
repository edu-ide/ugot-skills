

# 포트폴리오 참고 가이드와 적용 범위

2026년 9월 29일 확인했다. 글쓰기의 일반 판단에 참고하며, 특정 기업의 제출 규정이나 합격 기준으로 취급하지 않는다. 실제 공고·양식·글자 제한은 작성 시점의 원문을 우선한다.

- [Nielsen Norman Group — 5 Steps to Creating a UX-Design Portfolio](https://www.nngroup.com/articles/ux-design-portfolios/): 포트폴리오의 독자를 채용 담당자와 실무자로 보고, 그들이 이해할 방식으로 역량을 보여주라고 설명한다. 문제, 본인의 역할과 과정, 결과를 드러내며 훑어보기 쉽게 구성하는 원칙을 참고한다. **UX 디자인 포트폴리오 자료**이므로 권장 프로젝트 수나 디자인 산출물 구성을 개발자 포트폴리오의 필수 요건으로 옮기지 않는다.
- [Indeed — What Is a Work Portfolio? (How To Build One)](https://www.indeed.com/career-advice/resumes-cover-letters/build-your-work-portfolio): 목표 직무와 관련된 사례를 선택하고, 각 사례의 목적·역할·결과를 설명하며 이력서와 일관되게 정리하는 데 참고한다. 고정된 분량보다 적절한 사례와 명확한 구성이 중요하다는 조언이며 기업의 공식 선발 기준은 아니다.

이 스킬의 두괄식 구성, 사용자 승인 문장 보존, 체험과 실무 구분, AI가 한 검사를 사용자 습관으로 쓰지 않는 원칙은 이 가이드의 인용이 아니라 **실제 편집 대화에서 얻은 교정 원칙**이다.

외부 사례를 더 조사할 때는 요청된 글의 종류와 독자가 비슷한 자료를 고른다. 출처가 주장하는 범위를 표시하고, 모범 답안의 문장이나 성공담을 사용자의 경험으로 가져오지 않는다.
