# CriticMarkup으로 근거 연결하기

설명용 Markdown의 모든 의미 단위에 근거 상태를 남긴다. 문장·목록·표·인용·코드 설명·도식의 주장을 포함한다. 아래 필드와 검수 절차는 이 목적을 위해 정한 작성 규칙이다.

## 표기와 적용 범위

CriticMarkup은 추가 `{++ ++}`, 삭제 `{-- --}`, 대체 `{~~이전~>이후~~}`, 주석 `{>> <<}`, 강조 `{== ==}`를 제공한다. 강조 뒤에 주석을 붙여 대상 구절을 지정할 수 있다. {>>근거: 유형=사실; 출처=[공식 문법][syntax]; 위치=The Basic Syntax 및 Highlights; 확인=2026-10-15; 연결=다섯 표기와 강조 뒤 주석의 사용법<<}

- 기본은 주장 바로 뒤에 한 줄 주석을 붙인다. 여러 주장 중 일부만 뒷받침하면 문장을 나누거나 해당 구절을 강조한다. 문단 전체에 붙일 때는 모든 주장을 뒷받침하는지 확인한다.
- 제목에 사실·수치·판단이 있으면 근거를 붙인다. 주제명만 있는 제목, 구분선, 목록 번호와 같은 구조에는 별도 주장을 만들지 않는다. YAML frontmatter와 실행 코드에는 표식을 삽입하지 않고 바로 다음 주석에서 필드·줄·심벌을 지정한다.
- 표는 해당 셀에 주석을 넣는다. 행 전체에 하나를 붙이려면 대상 열과 각 주장의 대응을 명시한다. 주석 필드는 세미콜론으로 나눠 표의 파이프 구분자와 충돌하지 않게 한다. 코드·수식·Mermaid·이미지는 블록 밖에서 줄·함수·식·노드·캡션을 지정한다.
- 중첩·겹침 표식을 만들지 않고 주석 안에서 줄을 바꾸지 않는다. Markdown 링크와 강조 구문을 가로질러 표식을 열고 닫지 않는다. 기존 추가·삭제·대체 표식과 미승인 변경 상태를 보존한다. {>>근거: 유형=문법과 작성 규칙; 출처=[공식 문법][syntax]; 위치=Important Notes; 확인=2026-10-15; 연결=개행 회피와 Markdown 태그 전체 감싸기 권고를 따르고 변경 상태 보존을 추가 규칙으로 둔다<<}

## 주석에 넣을 정보

다음은 이 스킬의 근거 주석 형식이다. CriticMarkup 표준이 필드 이름이나 사실 검증을 제공한다고 설명하지 않는다.

```text
{>>근거: 유형=사실/규칙/해석/제안; 출처=실제로 확인한 자료 링크; 위치=절·줄·심벌·발언; 연결=이 자료가 뒷받침하는 정확한 주장; 확인=열람일; 버전=확인한 커밋·개정판; 한계=미확인 범위<<}
```

- `유형`, `출처`, `위치`, `연결`을 기본으로 쓴다. 변경 가능한 자료에는 `확인`, 확보한 버전에는 `버전`, 검증 범위가 좁으면 `한계`를 남긴다. 모르는 날짜·커밋·쪽수·실행 결과를 채워 넣지 않는다.
- 같은 자료는 Markdown 참조 링크로 재사용하되, 각 주석에 정확한 위치와 뒷받침 범위를 적는다. 긴 출력은 원본 로그·실험 기록·자료에 연결한다. 독자가 접근할 수 없는 자료라면 접근 범위를 밝히고 민감한 원문을 공개 문서에 복사하지 않는다.

## 근거의 종류를 구분하기

- **사실:** 원자료·코드·공식 문서·실행 산출물을 읽고 실제 주장을 뒷받침하는 부분에 연결한다. 검색 제목, 도구 목록, 테스트 코드만으로 본문 사실이나 실행 성공을 확정하지 않는다. 계산에는 입력값의 출처와 식을 함께 남긴다.
- **규칙·결정:** 원래 사용자 발언, 승인된 결정, 관리되는 정책을 연결하고 적용 범위를 보존한다. 과거 규칙의 원문은 그 규칙이 존재했다는 근거로만 쓴다. 규칙의 효과나 기술적 정확성까지 입증한 것으로 확대하지 않는다. 새 작성 관례는 작성자가 정한 규칙이라고 밝히고 이유를 적는다.
- **해석:** 확인한 사실과 결론 사이의 추론을 적는다. **제안:** 요구·제약과 선택 이유를 적고 예상 효과는 미검증으로 남긴다. 사용자 의도에 대한 발언을 구현 완료나 성과의 증거로 쓰지 않는다.
- **미확인:** 출처를 찾지 못했거나 열람하지 못했다면 `상태=미확인; 부족=필요한 자료`를 적는다. 확인된 부분과 분리하고 검증 완료로 집계하지 않는다. 단지 표식을 채우려고 관련 없는 링크나 같은 초안을 근거로 붙이지 않는다.

## 작성과 소급 적용

1. 요청된 문서와 자체 스킬의 실제 원본을 찾고, 링크·복사본·외부 배포본을 구별한다. 기존 결정·원자료·커밋·실행 기록을 먼저 확인한다. 문서 전체 적용 요청이면 기존 내용까지, 일반 수정이면 새로 쓰거나 바꾼 내용까지 적용한다.
2. 의미 단위별로 사실·규칙·해석·제안을 분류하고 근거를 대조한다. 출처가 오래되었거나 다른 환경·버전·대상에 한정되면 문장을 좁히거나 그 한계를 표시한다. 수치·조건·부정을 임의로 바꾸지 않는다. 새로 작성·수정하는 문서는 근거 없는 단언을 미확인 표현으로 고친다. 원문 보존이 요청된 소급 작업에서는 해당 구절을 미확인 대상으로 명시하고 본문이 검증되었다고 보고하지 않는다.
3. 기존 스킬의 유래를 복원할 때는 작성 당시 기록을 우선한다. 이전 커밋에 같은 문장이 있다는 이유로 당시 사건·실험·사용자 승인이 입증되었다고 쓰지 않는다. 원문만 확인되면 `유래=미확인; 효력=미검증`을 남기고 새 사용자 승인으로 소급 대체하지 않는다.
4. 본문·목록·표·인용·블록·캡션·사실이 있는 제목을 직접 대조한다. 표식 개수만 세어 의미상 누락이나 근거의 적합성이 검증되었다고 하지 않는다. 미확인 내용이 남으면 결과에서 범위와 필요한 자료를 밝힌다.
5. 문장을 고치면 근거도 다시 확인한다. 변경 수락·거절이나 배포 변환 뒤에도 주장과 근거의 연결이 남는지 확인한다. 출력 형식이 주석을 제거한다면 별도 근거 주석·각주로 보존하고 대응을 확인한다.

## 실제 문법을 근거로 한 예

CriticMarkup의 주석 표기는 `{>> <<}`다. {>>근거: 유형=사실; 출처=[공식 문법][syntax]; 위치=The Basic Syntax 및 Comments; 확인=2026-10-15; 연결=주석의 여는 표식과 닫는 표식<<}

CriticMarkup을 도입하면 우리 문서의 오류가 줄어들 것이라고 예상한다. {>>근거: 유형=제안; 출처=작성자 예상; 상태=미확인; 부족=도입 전후 문서 오류 비교; 한계=효과를 측정한 결과가 아니다<<}

[syntax]: https://github.com/CriticMarkup/CriticMarkup-toolkit
