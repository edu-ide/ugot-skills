# 조사 근거와 적용 기준

확인일: 2026-09-10. 아래는 출판·사용성 전문가의 자료이며, 한국 사주 앱 판매량이나 베스트셀러 달성 인과관계를 입증한 자료가 아니다. 정책의 현재 적용 여부는 사용할 때 다시 확인한다.

## 웹 조사

### 1. 책의 독자와 약속

[IngramSpark — Think Like a Publisher: Position Your Book Before You Write](https://www.ingramspark.com/blog/think-like-a-publisher-position-your-book-before-you-write), Linda Secondari, 2025-10-08.

출판 디자인 책임자의 실무 조언이다. 구체적인 독자, 비교 도서, 구매 맥락을 정한 뒤 형식·가격·디자인이 그 책의 약속을 뒷받침하도록 구성한다. 모든 사람을 위한 책이라는 설명은 독자 구분에 도움이 적다.

적용: 상품마다 독자의 질문을 하나로 명확히 적고 실제 목차가 그 질문을 다루는지 대조한다. 이것을 판매 보장 공식으로 사용하지 않는다.

### 2. 설명과 본문의 일치, 과도한 재사용

[Amazon KDP — Guide to Kindle Content Quality](https://kdp.amazon.com/en_US/help/topic/G200952510), 확인일 기준 공식 지침.

책 설명과 실제 내용의 불일치, 빠진 내용, 읽기 경험을 해치는 반복과 다른 책 사이의 과도한 재사용을 품질 문제로 다룬다. 독자가 기대한 내용을 받을 수 있는지가 중요하다.

적용: 표지와 템플릿이 다른 것만으로 독립 상품의 내용을 인정하지 않는다. 우리 앱은 KDP가 아니므로 이 지침을 앱의 법적 의무나 판매 금지 판정으로 전용하지 않는다. 일치율 하나로 표절·정책 위반을 판단하지 않는다.

### 3. 실제 본문을 살펴볼 수 있게 하기

[Amazon KDP — Read Sample](https://kdp.amazon.com/en_US/help/topic/G200644250), 확인일 기준 공식 기능 설명.

독자가 구매 전에 책 내부를 찾아보고 미리 읽을 수 있도록 하는 기능을 설명한다.

적용: 홍보용 표지뿐 아니라 실제 전달 PDF의 핵심 본문, 변화 이유, 근거 페이지를 보여준다. 예시가 특정 개인의 고정 샘플이면 그 상태를 표시한다. 우리 앱의 미리보기 비율이나 페이지 수를 KDP와 같게 만들 필요는 없다.

### 4. 의미 있는 이미지와 설명의 결합

[Baymard Institute — Structuring Product Page Descriptions by Highlights](https://baymard.com/blog/structure-descriptions-by-highlights), 사용성 연구 기반 해설.

제품의 개별 특징을 관련 이미지와 설명으로 묶으면 사용자가 차이를 살펴보는 데 도움이 된다고 보고한다.

적용: ‘48쪽’ 같은 사양만 나열하지 않고, 실제 본문 이미지와 ‘이 페이지에서 무엇을 알게 되는가’를 묶는다. 일반 전자상거래 사용성 결과를 사주 PDF 매출 상승률로 바꾸지 않는다.

### 5. 건너뛰어 읽어도 이해되는 구조

[Nielsen Norman Group — The Layer-Cake Pattern of Scanning Content on the Web](https://www.nngroup.com/articles/layer-cake-pattern-scanning/), Kara Pernice, 2019-08-04.

눈에 띄면서 내용을 정확히 요약하는 소제목, 관련 내용의 묶음, 명확한 정보 위계가 필요한 부분을 찾아 읽는 데 도움을 준다.

적용: ‘해설 / 원문 근거 / 조언’ 표제는 실제 내용과 맞아야 한다. 원문을 읽지 않는 독자도 핵심 해설을 이해할 수 있게 한다. 웹 관찰을 인쇄물 전체의 동일한 읽기 행동이라고 단정하지 않는다.

## 자체 편집 기준 — 연구에서 정해 준 숫자가 아님

| 검토 축 | 확인할 질문 | 필요한 증거 |
| --- | --- | --- |
| 독자 적합성 | 이 해설이 상정하는 생활이 실제 입력과 맞는가? | 판매 문구, 입력 항목, 본문 예시 |
| 약속 이행 | 제목의 핵심 질문을 어느 페이지가 풀어 주는가? | 약속과 페이지 매핑 |
| 차별성 | 공통 운세 외에 이 상품을 고를 이유가 있는가? | 전체 페이지 분류, 텍스트 대조, 수동 확인 |
| 깊이 | 특징의 이유를 알게 되는가, 표현만 반복하는가? | 연속 페이지와 근거 사슬 |
| 가독성 | 훑어 읽기와 자세히 읽기 모두 가능한가? | 실제 출력과 모바일 확인 |
| 신뢰 | 계산·해석·예시·미구현을 구분하는가? | 원문, 산식 버전, 전달 파일 |
| 운영 | 고객 입력으로 올바른 파일이 전달되는가? | 실제 입력부터 전달까지 검증 |
| 시장 | 구매·만족·추천의 근거가 있는가? | 기간과 분모가 있는 실제 관찰 |

‘특화 내용 70%’, ‘몇 쪽 이상’, ‘몇 점 이상이면 베스트셀러’ 같은 보편 임계값을 만들지 않는다. 쪽수 대신 약속한 질문이 얼마나 충분히 해소되는지 판단한다. 공유 페이지는 독자에게 설명하고, 중복 구매가 자연스러운 상품군에서는 특히 주의한다.

## 적용 사례와 오류 방지

- 인포그래픽 48쪽 중 많은 부분이 공통 운세라면 ‘재물운 해설 48쪽’이라는 인상을 주지 않는지 검사한다. 공통 내용을 삭제하는 것만이 답은 아니며, 재물이라는 관점으로 다시 해석했는지 본다.
- 전통 해석의 점수 하락은 현금·연봉 감소의 관측값이 아니다. 숫자를 유지한다면 계산 변화와 편집 해설을 분리하고, 해당 점수가 현실을 검증한 척하지 않는다.
- 남는 몫·계약 경계의 설명은 특정 직업 상황의 예시일 수 있다. 생년월일만으로 그 사람이 프리랜서이거나 계약 분쟁을 겪는다고 말하지 않는다.
- 아름다운 공통 자산은 재사용할 수 있다. 문제는 자산 재사용 자체가 아니라, 서로 다른 상품이 독자에게 사실상 같은 답을 주는 것이다.
