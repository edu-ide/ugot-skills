# blame-the-instrument-first — 자부터 의심

**원칙**: 나쁜 숫자는 대상의 한계이기 전에 자·조건·틀의 결함일 확률이 더 높다(기록: "0 → 외부 필요"로 결론 냈던 것들 대부분이 깨진 평가·희소 데이터·잘못된 틀이었다). 단, 변명 기계가 되지 않게 재판은 2회로 캡.

| 갈래 | 질문 | 예 |
|---|---|---|
| 계기 | 측정 코드가 맞나 | 40토큰 생성 평가 대신 teacher-forcing으로 잼 |
| 표본 | n이 충분한가, 편향은 | SQuAD 앞 150문항이 한 기사 |
| 조건 | 예산·설정이 비교 가능한가 | EMA가 한 팔에만 하중 |
| 절차 | 순서·누수·오염 | 보정 절반과 평가 절반이 섞임 |
| 목적 | 그 지표가 목표를 재나 | bpb로 디퓨전 리더를 잼 |
| 틀 | 문제 정의가 맞나 | 7개 레버가 전부 0.26 — 틀이 틀림 |

소프트웨어·제품에서도 같다: 테스트 실패·지표 하락을 "코드/기능 탓"으로 적기 전에 테스트·측정·조건을 먼저 본다.
