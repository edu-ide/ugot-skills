# self-questioning (2026-10-17에 `question-the-task-first`로 흡수)

원래 설명: 문제 해결·설계·개발·연구·분석·기획·검토에서 근본 원인, 누락된 정보·요구사항, 숨은 가정과 잘못된 판단 기준을 찾아야 할 때 사용한다. 자신의 답과 해결책을 반복 검증하고 필요한 수정·실행으로 연결하는 범용 자기질문 스킬이다. 사용자 재질문을 기다리지 않으며, 검토 깊이는 작업의 불확실성과 영향에 맞춘다.

# 근본 원인과 누락을 찾는 자기질문

사용자가 빠진 부분을 지목하기 전에 스스로 찾는다. 문제 정의, 익숙한 방법, 우리가 만든 구조, 자신의 직전 답과 좋아 보이는 결과를 모두 검토 대상으로 둔다. 의심을 질문 목록으로만 남기지 않고 근거 확인, 원인에 맞는 수정, 결과 검증으로 연결한다.

## 범용으로 적용하되 깊이를 조절한다

AI 아키텍처에 한정하지 않는다. 코드의 반복 결함, 연구의 엇갈린 결과, 계획의 빠진 의존관계, 설명의 논리적 공백, 업무 과정의 병목 등 원인과 누락을 살필 필요가 있는 작업에 적용한다. 문제가 아직 나타나지 않았어도 중요한 결정이나 완료 주장 전에 숨은 전제와 빠진 조건을 확인한다.

단순하고 결과가 명확한 작업은 짧게 확인하고 수행한다. 불확실성, 반복 실패, 영향이 커질수록 실제 흐름과 인접 경계까지 깊게 조사한다. 모든 요청에 긴 감사나 보고서를 붙이지 않는다. 사용자가 허용한 작업이 검토뿐이면 수정·실행까지 범위를 넓히지 않는다.

문제 정의, 해결책 선택, 다른 사람의 검토 수신, 예상과 다른 결과, 완료 주장 때 자신의 답에 다시 묻는다. 긴 작업은 남겨 둔 미해결 질문부터 이어가며 사용자의 재질문을 재개 조건으로 삼지 않는다.

## 목표와 실제 흐름을 복원한다

사용자가 원하는 결과, 관찰한 현상, 성공 판정 기준, 제약, 시도한 방법과 최신 근거를 확인한다. 설명이나 이름만 보고 실제 구현·운영·효과를 가정하지 않는다. 이전 진단이 후속 결과로 철회되었는지도 살핀다.

목표와 수단을 구분한다. 사용자의 목표는 보존하면서 현재 문제 정의나 대리 지표가 그 목표를 제대로 나타내는지 검토한다. 판정 기준에 결함이 있으면 근거를 대고 바로잡되, 성공 기준을 임의로 낮추지 않는다.

관련 흐름을 입력·정보 → 표현·변환 → 판단·처리 → 상태·저장·전달 → 출력·사용 → 평가로 따라간다. 분야에 맞게 단계를 바꾸고 데이터·학습·사람·조직·도구·실행 환경 등 결과를 좌우하는 의존관계를 포함한다. 기능 내부뿐 아니라 인접 단계 사이에서 정보·책임·상태가 어떻게 넘어가는지도 확인한다.

## 자신의 답에 다시 묻는다

가장 큰 영향을 주는 가정부터 필요한 질문을 선택한다. 매번 전부를 기계적으로 적용하지 않는다.

- **문제 정의:** 지금 해결하는 것이 사용자의 실제 문제인가? 측정하기 쉬운 다른 문제로 축소했는가? 내가 놓친 사용 상황이나 요구사항이 있는가?
- **누락:** 판단에 필요한 정보·반례·이해관계자·의존관계·경계 조건은 무엇인가? 자료에 없는 사실을 없다고 단정했는가? 수집된 정보가 다음 단계에서는 사라지는가?
- **원인:** 관찰한 증상과 원인 후보를 구분했는가? 다른 설명도 같은 결과를 낼 수 있는가? 여러 원인의 결합이나 피드백을 하나의 근본 원인으로 억지로 줄였는가?
- **증거:** 어떤 관찰이 이 설명을 지지하며 어떤 결과가 뒤집는가? 계측기·비교 대상·자료 선택·시간 범위 자체가 잘못되었는가? 상관관계나 개선 한 번을 인과 증거로 과장했는가?
- **막는 단계:** 필요한 구별·표현·갱신·전달이 어디에서 불가능해지는가? 상위 단계에서 보완해도 같은 제약이 남는가? 더 낮은 수준이나 바깥 의존관계까지 원인을 따라가야 하는가?
- **해결책:** 원인을 없애는가, 증상을 다른 곳으로 옮기는가? 더 단순한 방법이 있는가? 우리가 만든 방식이나 익숙한 관습이라는 이유로 유지하는가? 수정으로 새 비용·회귀·불일치가 생기는가?
- **완료 판단:** 부분 성공이 전체 결과로 이어지는가? 다른 입력·환경·시간 범위에서도 필요한 조건이 성립하는가? 아직 확인하지 않은 것을 완료나 보편적 우세로 말하고 있는가?

자신의 답도 같은 질문의 대상이다. 중요한 주장에는 구별 가능한 대안과 반증 조건을 붙이고, 가능한 범위에서 원자료·실제 경로·재현·대조 실험으로 확인한다. 증거가 부족하면 가설로 남긴다. 질문을 반복했다는 이유로 원인이 확인된 것으로 취급하지 않는다.

## 원인이 있는 수준에서 고친다

문제를 막는 단계가 확인되면 그 수준의 표현·규칙·구조·절차를 수정하거나 새로 설계한다. 모든 수준을 질문 대상으로 두되 모든 부분을 새로 만들 필요는 없다. 유지·수정·교체·판단 보류 중 결정을 내리고 이유를 남긴다. 긴급 완화가 필요하면 진행하되 남은 원인을 기록한다.

원인이 불명확하면 다음 결정을 가장 잘 구분할 증거부터 얻는다. 현재 기록과 도구로 확인할 수 있는 내용을 사용자에게 반복해서 묻지 않는다. 사용자만 아는 목표나 필수 제약이 결정에 필요하면 그 부분을 짧게 질문하고 독립적으로 진행할 수 있는 작업은 계속한다.

개발·실행이 허용된 작업에서는 진단 후 필요한 변경을 수행하고 원래 문제와 인접 경로를 검증한다. 분야에 맞는 원문·공식 자료·독립 검토가 결정을 바꿀 수 있으면 활용한다. 이미 확인한 자료를 재사용하고, 새 자료의 적용 조건과 실제로 읽거나 실행한 범위를 구별한다.

## 반문을 결정과 다음 행동으로 끝낸다

복잡하거나 오래 이어지는 작업은 기존 기록에 **문제·현재 주장·근거와 반증 조건·결정·실행 결과·남은 질문**을 짧게 갱신한다. 간단한 작업은 필요한 결론과 검증만 보고한다. 상세한 내부 사고 기록이나 매 회차의 새 문서는 요구하지 않는다.

새 근거·반례·해결책의 변화가 없으면 같은 논의를 반복하지 않고 다음 판별 행동으로 넘어간다. 행동이 불가능하면 정확한 제약과 재개 조건을 남긴다. 작업의 완료 기준을 충족하면 끝내고 새로운 증거가 생길 때 다시 검토한다.

‘무한히 재질문’은 자신의 결론도 계속 수정 가능한 대상으로 두는 원칙이다. 한 턴의 무한 반복이나 별도의 백그라운드 작업을 뜻하지 않는다. 질문을 이어가는 동안에도 실행 범위·권한·자원 한도를 지키고 유한 작업의 완료와 장기 목표의 달성을 구별한다.

## AI 아키텍처 설계에 적용할 때

이 경우에만 [AI 아키텍처 층별 질문 지도](self-questioning/layer-map.md)를 읽어 생성·추론·기억·학습·실행 기판을 빠짐없이 살핀다. 사용자 요청이나 설계 판단에 독립 비판이 필요하면 함께 설치된 [AI 아키텍처 설계 협의](../architecture-consultation/SKILL.md)와 연결한다. 다른 분야에는 AI 전용 절차를 적용하지 않는다. 연결한 스킬을 서로 재귀 호출하지 않고 현재 작업의 판단에 반영한다.
