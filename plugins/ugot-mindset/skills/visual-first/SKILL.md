# visual-first — 시각화 먼저

## 왜 (이 스킬이 막는 실수)

2026-10-17, "JPA 를 JDBC 나 jOOQ 로 바꾸면 쿼리 추상화가 안 되냐"는 질문에 비교표 두 개와 전문용어(객체 그래프, 방언, 집합체, 영속성 컨텍스트)부터 냈다. 정작 바꾸자는 이유인 "Hibernate 엔진이 메모리를 먹는다"는 한 번도 말하지 않았다. 사용자: "왜 나에게 설명이 불친절해" → "시각화 설명 원칙 만들자".

짧게 쓰기(`answer-briefly`)와 쉬운 말(`speak-human`)은 이미 있었지만 구조를 전달하지 못했다. 표는 이미 아는 사람이 값을 대조하는 도구다. 처음 듣는 사람에게는 **무엇이 어디에 있고, 무엇이 무엇을 일으키고, 선택지마다 무엇이 빠지는지**를 한눈에 보여 주는 그림이 필요하다. 그림을 그리려면 구조를 먼저 이해해야 하므로, 그림은 설명하는 쪽의 이해도 검사한다.

## 질문 모양 → 그림 모양

| 질문 | 그림 | 예 |
|---|---|---|
| 무엇이 어디서 무엇을 하나(구조·작동 원리) | 층이나 상자와 화살표, 문제가 생기는 곳에 표시 | 앱 → JPA 규칙 → Hibernate 엔진 → DB, 메모리 먹는 칸에 색 |
| 어떤 순서로 일어나나(흐름·사고) | 시간 줄, 단계 넘기기 | 요청이 들어와 실패하는 단계까지 |
| 무엇이 다른가(선택지 비교) | 같은 구조 그림 위에 선택지마다 무엇이 남고 빠지는지 겹쳐 표시 | QueryDSL 은 엔진 위에 얹힘, JDBC 는 엔진을 뺌 |
| 얼마나(수치·변화) | 막대나 선 하나, 기준선·한도선 표시 | 서비스별 메모리와 노드 한도 |
| 왜(원인 사슬) | 위에서 아래로 내려가는 사슬, 우리가 바꿀 수 있는 원인에 표시 | 증상 → 직접 원인 → 우리 원인 |
| 어디까지 가나(단계·로드맵) | 계단, 지금 위치와 멈출 단 표시 | 설정 → 확장점 → 포크 → 교체 → 재작성 |
| 왜 이게 있나·왜 안 빼나·다른 데선 어떻게 하나(개념·선택) | 개념 지도 + 왜 사슬(아래 절) | Hibernate 는 왜 있고 Spring 은 왜 두고 Rust 는 뭘 하나 |

## 규칙

0. **네 상황에선 필수, 건너뜀 사유는 셋.** (2026-10-20 사용자 "왜 visual-first 스킬은 계속 무시되는 거 같지, 스킬 설계에 문제가 있나?") 진단 — ①항상-켜짐 "3줄·표 금지"와 부딪히면 글을 택했고 ②트리거가 넓어 모든 답에 걸려 소음이 됐고 ③도구 호출 두 번의 마찰 ④"해당없음" 건너뜀이 검사 없이 통과됐다. 고침 — 의도·설계 계보 / 후보 ≥3 × 자 ≥2 비교 / 추세 / 원인 사슬 ≥3단에서는 그림이 필수이고, 건너뜀 사유는 `이미됨`(그림이 이미 있음, 링크) · `글로요청` · `구조없음`(단일 숫자 상태 보고)뿐이다 — 장부 게이트가 이 스킬의 `skip_reasons`로 검사한다. **그림 + 3줄이 짧은 답이다**: answer-briefly의 3줄은 그림 아래 글의 길이다. Code 탭에선 `show_widget`에 SVG 한 번(read_me는 세션당 한 번) — 두 번째 호출을 핑계로 삼지 않는다.
1. **그림 먼저.** 결론 한 문장 다음에 바로 그림을 둔다. 표와 목록은 그림 다음, 값 대조가 꼭 필요할 때만 쓴다. 그림은 표가 아니므로 표를 줄이라는 규칙과 부딪히지 않는다.
2. **한 그림 한 생각.** 생각이 둘이면 그림 둘 또는 단계 넘기기.
3. **전제를 그림 안에.** "왜 이 얘기를 하나"가 그림 제목이나 첫 칸에 보이게 한다. 질문 뒤의 진짜 질문(`read-the-intent`)의 답이 그림 첫 줄이다.
4. **라벨은 사람 말.** 전문용어는 풀어 쓰고, 정식 이름은 곁에 작게 둔다. 장부 번호·코드 이름·괄호 주석을 그림에 넣지 않는다.
5. **그림 아래 글은 세 줄 이내.** 어디를 보면 되는지, 결론, 다음 할 일.
6. **숫자는 출처 있는 것만.** 추정은 그림에서도 점선이나 흐린 색으로 다르게 보인다.
7. **자기 점검.** 그림만 보고 원래 질문에 답할 수 있나? 못 하면 다시 그린다.

## 종합 설명 — 개념 지도와 왜 사슬

"왜"는 한 번에 끝나지 않는다. 한 단계만 답하면 상대가 다음 "왜"를 계속 물어야 한다(2026-10-17: 왜 바꾸나 → Hibernate 는 왜 있나 → 왜 빼나 → Spring 은 왜 안 빼고 Rust 는 뭘 하나, 네 번). 개념이나 선택을 설명할 때는 처음 답에 두 장을 같이 낸다.

1. **개념 지도 한 장.** 왼쪽에서 오른쪽으로: 어떤 **문제**가 있었나 → 그 문제를 **이것이 어떻게 푸나** → 그 대가로 **무엇을 치르나** → 같은 문제를 **다른 언어·도구·시대는 어떻게 푸나**(같은 축 위에 나란히, 무엇이 어디서 일어나는지가 차이로 보이게) → **우리는 지금 어디 있고 어디로 갈 수 있나**. 차이를 하나의 축으로 잡는다(예: 번역이 실행 중이냐 빌드 때냐 컴파일 때냐).
2. **왜 사슬 한 장.** 독자가 다음에 물을 "왜"를 질문으로 미리 보이고, 누르면 답이 열린다. 다음 질문은 앞 답이 꺼낸 주장의 "왜"다(옆 개념으로 새지 않는다). 개념 사슬은 지식에서 시작해 **우리 결정**에서 끝난다: 왜 있나 → 왜 아직 쓰나 → 다른 데선 → 우리도 그렇게 할 수 있나 → 그래서 우리는. 사고 설명이면 같은 방식으로 "무엇이 바뀌었나"를 한 번 넣고 우리가 바꿀 수 있는 원인까지 내려간다.

점검: 상대가 이어서 물을 만한 "왜" 세 개를 먼저 적어 보고, 그 답이 지도나 사슬 안에 있는지 본다. 없으면 아직 한 단계 답이다.

## 도구 — 사용자 자산으로 남는 것 먼저

그림은 사용자의 이해를 쌓는 자산이다. 호스트 안에만 남는 그림은 대화가 끝나면 사용자 것이 아니다.

1. **이 호스트가 Space 위젯을 그리는지 먼저 본다.** Code 탭은 앱이 관리하는 서버(확장 .mcpb·커넥터)의 위젯만 그린다. Claude Code 설정 서버의 위젯은 텍스트로 떨어진다. 터미널·Codex는 그리지 않는다.
2. **그려지면** 그림은 `brain_visual_show`, 보드는 `brain_canvas_show`(📌하면 vault `visuals/`·`.canvas`).
3. **안 그려지면** 그 자리 방식(호스트 위젯, 글자 그림, mermaid)으로 보이고, 같은 그림을 `brain_artifact_ops save`로 vault `visuals/`에 남긴다. 호스트 전용으로 끝내지 않는다. 긴 설명은 Space 노트가 먼저고, Artifact는 외부 공유용 사본이다.
4. 라이트·다크와 좁은 화면에서 읽히는지 본다.

저장 형식·경로·확장 설치는 [references/space-assets.md](references/space-assets.md)에 있다.

## 하지 않는 것

- 설명 대신 비교표부터 내기.
- 장식용 그림(내용 없는 아이콘·일러스트).
- 예/아니오나 한 줄로 끝나는 사실 질문에 그림 강요. 그때는 한 줄로 끝낸다.
- 그림을 그렸다고 글을 길게 늘이기.

## 흡수: answer-briefly → 이 스킬의 "글 칸" (2026-10-20, 사용자 "answer-briefly를 제거하고 visual-first가 그 경로를 차지하면 되지 않아?")

**탄생 (옛 answer-briefly, 2026-10-08 20:12 KST)**: 사용자 "왜 이렇게 말이 길어 간단하게 이야기해" → "이제 이렇게 간단하게 이야기하게 스킬 만들자". 그날 저녁 내 답은 매번 300~600단어·표 2~3개·배경 설명·자기 반성 서술이 붙어 있었다. 사용자가 원한 건 결론이었다. 2026-10-20 사용자가 두 스킬의 충돌(3줄 법이 그림을 빼는 핑계가 됨)을 보고 하나로 합치자고 했다 — 답의 모양은 한 주인이 갖는다.

글 칸의 규칙 (항상 적용, 사용자가 "자세히/길게/전부"라고 하기 전까지):
1. **결론이 첫 문장.** 질문이 "왜/맞지/가능해?"면 첫 문장이 예/아니오/숫자.
2. **3줄 또는 3항목 이내.** 더 할 말이 있으면 "더 볼까요?" 한 마디로 끝낸다. 네 상황에선 그림이 그 앞에 온다 — 그림 + 3줄이 짧은 답이다.
3. **표·배경·역사·자기 반성·과정 서술 금지.** 근거는 한 구절(장부 번호·숫자 하나)로만. 그림은 표가 아니다.
4. **문서·수치는 링크 하나.** 본문에 옮겨 적지 않는다.
5. **진행 보고도 같은 규칙**: 무엇이 끝났고(숫자), 다음이 무엇인지, 언제. 세 줄.
6. 길게 쓰고 싶은 충동 = 문서로 보내라(파일에 쓰고 링크만).
