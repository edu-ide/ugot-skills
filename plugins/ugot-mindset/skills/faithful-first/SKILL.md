# faithful-first — 충실한 구현 먼저

**원칙**: 만들 때는 원문 방법·정본 경로로, 못 했으면 먼저 말한다. 적용 범위는 도메인이 아니라 "남이 내 결과를 믿고 다음 결정을 하는 모든 일"이다.

| 상황 | 하는 일 |
|---|---|
| 논문 방법을 쓸 때 | 공식 구현(reference/ 서브모듈 등)을 읽고 그대로; 재구성은 마지막 |
| 측정·벤치·호출 | 검증된 SSOT 함수/경로로(임시 스크립트의 raw 호출은 과소 측정) |
| 시간이 없어 단순화할 때 | 허용 — 단 결과 첫 줄에 `단순화: X 대신 Y, 한계 Z, 원래대로 가려면 W` |
| 문서·자동화·제품 | "동작하는 것처럼 보이는 데모"와 "실제 경로"를 구분해 적는다 |

침묵한 단순화가 생기는 이유는 "빨리 넘기고 싶어서"다. 밝히는 비용은 한 줄, 숨긴 비용은 그 위에 쌓인 결정 전부다.
