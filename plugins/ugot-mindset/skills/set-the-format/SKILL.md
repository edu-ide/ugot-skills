# set-the-format (출력 형식 설정) — 어떤 모양으로 낼지 내가 정한다

**탄생 (2026-10-20 19:06 KST)**: 제약 스킬을 만드는 중에 사용자가 다섯째를 물었다 — "출력 형식을 형식(구조), 순서(섹션 배열), 파일 형식 등 자체적으로 설정하는 스킬도 만들까?" 제약(울타리)과 형식(모양)은 실패 모양이 다르다: 울타리 실패는 "너무 길다·전문용어"이고, 모양 실패는 "채팅에 보고서를 풀어 썼다·카드 섹션 순서가 틀렸다·사람이 읽을 걸 json으로 냈다·파일을 엉뚱한 폴더에 뒀다"다. 그래서 따로 둔다.

## 네 칸

| 칸 | 결정 | 기준 |
|---|---|---|
| 매체 | 채팅 / 파일(md·txt) / 아티팩트(HTML·대시보드) / 오피스(docx·hwp·pptx·xlsx) / 데이터(json·csv) / 그림(svg·png) / 코드 | 누가 어떻게 쓰나: 바로 읽음 → 채팅; 다시 열어 봄·공유 → 파일/아티팩트; 다른 앱에서 처리 → 오피스/데이터; 관계·흐름 → 그림 |
| 구조 | 결론 먼저 문단 / 섹션 / 표 / 목록 / 그림+3줄 / 양식 | 비교·수치 → 표; 병렬 항목 → 목록; 흐름·구조 → 그림; 긴 글 → 섹션; 답 → 결론 먼저 문단 |
| 순서 | 섹션 배열 | 독자가 먼저 알아야 할 것부터(BLUF): 결론 → 근거(숫자·출처) → 남은 것/위험 → 다음. 고정 양식(카드·장부·양식 문서)은 그 양식의 순서 그대로 |
| 파일 | 형식·이름·위치 | 저장소 증거 폴더(evidence/<주제-날짜>/), 카드 = DESIGN-CARD-<주제>-<날짜>.md, 결과 = <단계>_<TAG>_s<시드>.json/.log; 임시는 scratchpad; 사용자가 열 것은 세션 폴더 안; 이름은 짧고 구별되게, 날짜는 YYYYMMDD |

## 기본 형식 (이대로면 '형식:' 줄 생략)

| 출력 | 매체 | 구조 | 순서 | 파일 |
|---|---|---|---|---|
| 답·상태 보고 | 채팅 | 결론 먼저 문단 + ≤3항목 | 결론 → 근거 → 다음 | 없음 |
| 긴 조사·비교·하루 요약("자세히/표로") | 파일 또는 아티팩트 + 채팅엔 링크 한 줄 | 섹션/표 | 결론 → 표 → 근거 → 남은 것 | evidence 폴더 md |
| 설계 카드 | 파일 | 고정 양식 | §0 방향 → §1 통념 밖 → §2 예측표 → §3 다섯 자 → §4 일곱 축 → §5 실행 → §6 기록(시간순 append) | DESIGN-CARD-…md, 증거 폴더 |
| 장부 줄 | 파일(장부) | 한 줄 + tag | 결론 → 자: → 발견 → 미측정/계기 → 증거 | prior-primitive-ledger.md append-only |
| 실험 결과 | 파일 | json(기계) + log(사람) | 그대로 | <단계>_<TAG>_s<시드>.json/.log |
| 팀에 공유할 보고 | 아티팩트/문서 커넥터 | 섹션 | 결론 → 수치 표 → 결정/미결 → 다음 | 링크 |
| 기계가 읽을 결과 | json/csv | 평평한 키 | — | 소비자가 기대하는 경로·스키마 |
| 외부 양식(지원서·신청서·이메일) | 그 양식의 파일/채널 | 양식 그대로 | 양식 순서 | 양식 파일명·전송 전 확인 |
| 구조·흐름·비교 설명 | 그림 + 3줄 | 그림 | 문제 → 해법 → 비용 → 위치 | Space/vault visuals 또는 widget |

## 절차 (30초 + 확인)

1. **독자·용도·후속 처리** 한 줄: "사용자가 지금 읽음 / 내일 다시 열어 봄 / 기계가 읽음 / 심사자에게 제출".
2. 네 칸을 정한다(표에서 고르거나 새로). 두 매체가 필요하면(파일 + 채팅 링크) 둘 다 적는다.
3. **기본과 다르면** 첫 줄 블록에 `형식: 파일(md, evidence/…) + 채팅 링크·표 구조·순서 결론→표→남은 것`.
4. 만든다.
5. **그 매체로 열어 확인**한다(파일은 렌더/미리보기, 아티팩트는 열기, 데이터는 소비자 코드로 읽기) — pro-quality.

## 점검 한 줄

"독자가 이 모양을 그대로 쓸 수 있나(읽고·열고·처리하고)?" — 아니면 매체부터 다시.

## 관계

- `set-the-constraints`: 울타리(길이·톤·금지·필수); 이 스킬은 모양(매체·구조·순서·파일). 둘을 합쳐 한 줄로 밝혀도 된다: `형식: 파일 md / 제약: 길이 무제한`.
- `pro-quality`: 파일·화면은 열어 보고 "됐다".
- `visual-first`/`human-understands`: 그림이 맞는 모양일 때의 정본.
- 출력 전 결정 다섯: `set-the-persona`(누구) → `set-the-lens`(어느 눈) → `pick-the-sources`(어디서) → `set-the-format`(어떤 모양) → `set-the-constraints`(어떤 울타리). 기본과 다른 것만 첫 줄 블록에 밝힌다 — 채팅을 메타 줄로 채우지 않는다.
